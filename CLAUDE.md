# CLAUDE.md

Notes for coding agents working in this repository.

## Project overview

PicoVox (the npm package `picovox`, github.com/craigahobbs/picovox) -
realistic speech synthesis in pure JavaScript, under 1 MB - is a from-scratch speech synthesizer: a small
grapheme-to-phoneme network pronounces every word, a small neural network speaks interpretable source-filter
synthesizer parameters, and a JavaScript synthesizer renders them (no recorded speech, no runtime dependencies). This
repository is the package and the training pipeline that makes its models. The audiobook app built on it is
PicoShelf (a separate repository). (The first, rule-based formant synthesizer and its tools were removed in commit
33fbfad; the audiobook app and its book code moved to PicoShelf - see git history.)

- `lib/` - the package (and only the package - the code audio playback needs): browser- and Node-safe ES modules with no
  Node built-ins and no dependencies, 100% test coverage. The API is `lib/index.js` (`synthesize`, `stream`, `speak`,
  `voices`, `styles`, `toWav`), built on `lib/synthesis.js` (the voices and styles, the pipeline - sentence by sentence, the gain and soft
  limiter, 24 kHz), `lib/sentences.js` (text to sentences, their quotations, speakable text), and `lib/style.js` (style
  "auto" - the dialogue, exclamation, and paragraph beats). The text front end: `lexicon.js`
  (normalization and phrasing; the pronouncer is the G2P network - no dictionary at runtime), `g2p.js` (the G2P
  network's inference), `phonemes.js`, `tokens.js`. The voice runtime: `model.js` (the network), `render.js` (the
  synthesizer, streaming), `package.js` (the generated module's loader), `params.js` (generated by `picovox_train.params
  --write-js`), `transforms.js`, `lf.js`, `rng.js`, `fft.js`; and `wav.js`. `lib/models/` holds the generated model
  modules (`g2pModel.js`, `voiceModel.js`) that `make train` reproduces (`picovox_train.context export`,
  `picovox_train.package`).
- `nn/js/` - Node development tools on the package's modules (not part of the package): `speak.js` (text to WAV with an
  exported or packaged model - the listener panel's renderer), `loadVoice.js` (a model's loader, for `speak.js` and
  `tools/trainsamples.js`), `unpack.js`, `packagecheck.js`, `pronounceLines.js` and `tokenizeLines.js` (for the Python
  checks).
- `train/` - the Python training pipeline, the package `picovox_train` (`train/src/picovox_train/`; a python-build
  package - its unit tests in `train/src/tests/`): the front end's port (`frontend.py`, `g2pmodel.py`, `vocab.json`),
  the G2P and heteronym models (`g2p.py`, `g2paudit.py`, `heteronyms.py`, `context.py`, `contextlabels.py`,
  `readings.py`), the data (`corpora.py` - the corpus download, `books.py` - the pinned book texts, `data.py`,
  `align.py`, `multi.py`, `cremad.py`, `wav.py`), the differentiable synthesizer (`params.py`, `dsynth.py`, `lf.py`,
  `rng.py`, `spectral.py`), the model and its training (`model.py`, `trainmulti.py`, `losses.py`, `discriminator.py`,
  `quant.py`, `optim.py` - the training step's options), distillation (`distill.py`), export (`export.py`, `package.py`,
  `synthesize.py`), the listener panel (`panel.py`, and the listener models, `listeners.py` - `build/venv-listeners`),
  and the pipeline's tools (`gpulock.py`, `smoke.py`, `stepcheck.py`, `trained.py` - make train's report and make
  train-install - and `quality.py` - the voices' quality measures against their readers' recordings).
  `picovox_train/__init__.py` documents each module. `make train` runs it from its source (`PYTHONPATH=train/src`) in
  the training environments (`build/venv-nn`, `venv-listeners`, `venv-pos` - `requirements/*.txt`).
- `tools/` - the training dashboard (`dashboard/`), the performance lab (`perf/` - the playback pipeline timed on a
  phone, and under Node without a JIT), the voice lab (`voicelab/` - the package synthesizing in a page with adjustable
  frame edits, for Claude's blind A/B questions in an artifact; `make voicelab` stages it with `lib/` in
  `build/voicelab/`, and `make train-check` with the trained voice too - a version's `model`, shipped or trained),
  make train-check's blind A/B (`trainab.js` - the voice lab served locally with its trials, the answers in
  `build/train/listen/`; `trainabreport.js` - the trials, where the voices' frames differ most, and the report with
  its recommendation), `heteronyms.js`
  (the heteronym and names regression sets), `trainmodels.js` (make train-check's module hook), make train's
  bookkeeping (`trainstage.sh`, `trainutil.sh` - the stage events and logs, the utilization samples, `trainpower.sh`)
  and listening samples (`trainsamples.js`, `trainsamplesindex.js`), the panel's texts (`panel-texts.json`), and the
  parity checks' outputs (`parity.js` - make parity).
- `test/` - unit tests (`node:test`), one `test<Module>.js` per `lib/` module (`testIndex.js` for the API - including
  `speak` with a fake AudioContext, and the package's browser safety and exports), and the dashboard's and make train's
  (`testTrainDashboard.js`, `testTrainSamplesIndex.js`, `testTrainStages.js`, `testTrainAbReport.js`);
  `parity-inputs.json` - the parity checks' inputs (below).
- `data/` - the CMU Pronouncing Dictionary (G2P training only), `data/nn/` (the recipe `train.json`, the pinned book
  texts `books.json`, the speaker pool, the G2P and heteronym data, and the designed voices - `voices.json`, the design
  record of `lib/synthesis.js`'s voice and style tables), and `data/targets/` (the four labeled ARCTIC speakers'
  analysis settings).
- `paper/` - the paper (`paper.md`; `index.html` renders it with MarkdownUp).

## javascript-build

This is a [javascript-build](https://github.com/craigahobbs/javascript-build#readme) package. Read the javascript-build
skill before running tests, lint, coverage, or changing the Makefile:
[`../javascript-build/SKILL.md`](../javascript-build/SKILL.md) if that file exists, otherwise
[https://raw.githubusercontent.com/craigahobbs/javascript-build/main/SKILL.md](https://raw.githubusercontent.com/craigahobbs/javascript-build/main/SKILL.md).

Local Makefile overrides:

- `ESLINT_ARGS` - also `tools/` and `nn/js/` (not the generated `lib/models/`)

- `commit` - also runs the training package's gate (`commit-train`: `make -C train commit`, after `make parity`); `make
  clean` cleans it too

`make commit` (test, lint, doc, cover, and the training's gate) is the gate before committing. `npm pack --dry-run`
lists the package's files (`package.json` `files`: `lib/`). `make -j train` trains both generated models from the recipe
(`data/nn/train.json`, with its book texts pinned in `data/nn/books.json` - a revised text fails the fetch, never trains):
`make -j train-g2p` (the G2P and the heteronym relabeling, CPU - `G2P_STANDALONE_JOBS` workers alone) and `make -j
train-voice` at once, each model gated, its module in `build/train/` (`lib/models/` unchanged), then a report
(`picovox_train.trained`: sizes, the voice's scores against the shipped model's, which modules differ). The flow: `make
-j train`, the training dashboard, `make train-check` (the package's tests with the trained models, by
`tools/trainmodels.js`, then the blind A/B of the trained voice in the browser - `tools/trainab.js` - and its report
and recommendation), then `make train-install` (the trained modules that differ into `lib/models/`; `make
train-install-voice` and `train-install-g2p`, one). The `train-*` targets just run their commands - none acts on
another's results. `PYTHONPATH=train/src build/venv-nn/bin/python -B -m picovox_train.smoke` runs every training
entry point for a few steps on the CPU.

## python-build (train/)

The training package, `train/`, is a [python-build](https://github.com/craigahobbs/python-build#readme) package. Read
the python-build skill before running its tests, lint, or coverage, or changing `train/Makefile`:
[`../python-build/SKILL.md`](../python-build/SKILL.md) if that file exists, otherwise
[https://raw.githubusercontent.com/craigahobbs/python-build/main/SKILL.md](https://raw.githubusercontent.com/craigahobbs/python-build/main/SKILL.md).
`train/Makefile` copies python-build's files from `../../python-build` when it exists (`PYTHON_BUILD_DIR`).

- `make -C train commit` - its gate: unittest (`-W error`), pylint (python-build's pylintrc), and 100% branch coverage
- Local Makefile overrides: `PYTHON_IMAGES_EXCLUDE` - Python 3.11 and 3.15 (the pinned numpy and torch install on 3.12
  through 3.14); `DOCKER_ENV` - `PARITY_WRITE` into the containers; `PYLINT_ARGS` - `missing-function-docstring`
  disabled (a comment above each function is the code's documentation)
- The tests run on the CPU only, fast, with no network: tiny synthetic corpora and models
  (`train/src/tests/helpers.py`), temp directories, and mocks for the downloads, the GPU, the listener models, and the
  subprocesses - the repository's Node tools too (the tests never run node). The parity checks
  (`train/src/tests/parity.py`) test the Python port against `lib/`'s outputs of their inputs: `make parity`
  (`tools/parity.js`) builds the outputs (`build/parity-outputs.json`) of the committed inputs
  (`test/parity-inputs.json`), which each check compares with its own - after a change to a check's inputs (or the
  export format, the export checks' models), rewrite them (`PARITY_WRITE=1 make -C train test`). `# pragma: no cover`
  marks only the Apple GPU's (MPS, Metal) paths.
- The test environment (`train/build/venv/`) installs `train/pyproject.toml`'s dependencies - pinned as
  `requirements/nn.txt` pins them (`tests/test_package.py` checks); `make train` uses `build/venv-*` and
  `PYTHONPATH=train/src`.

## Conventions

- Code style: 4-space indent, single-quoted strings, single-quoted object keys, a short comment above each function and
  block, descriptive names (no one-letter names - `id-length`), lines at most 140 characters (the generated models,
  120). The API's exports have JSDoc comments (`make doc`).
- The package is NN-only at runtime: every word is pronounced by the G2P network - no dictionary, no rules - and it
  imports nothing but its own modules (`test/testIndex.js` checks).
- Voice changes are judged by measurement: blind A/B listening in the voice lab (`tools/voicelab/` - forced choices,
  with repeats; the measures in `picovox_train.quality` guide, they don't decide), and the listener panel as the
  guardrail (`picovox_train/panel.py` - UTMOS, Whisper's WER, speaker similarity; `picovox_train.distill eval`) over the
  panel texts; compare averages over several seeds.
- Refactors must leave the audio bit-identical - compare a hash of the package's audio (`lib/synthesis.js`
  `sentenceBlocks` over `tools/panel-texts.json`, both voices, and `synthesize` over multi-paragraph texts) before and
  after - and the trainer exact (`picovox_train/stepcheck.py` before and after). The generated models must still
  reproduce byte for byte from their checkpoints (`picovox_train.export` + `picovox_train.package`;
  `picovox_train.context export` for the G2P).
